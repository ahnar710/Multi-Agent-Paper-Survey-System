# 论文调研多 Agent 系统：产品使用与讲解手册

## 1. 这个产品解决什么问题

用户输入一个产品或技术问题，系统自动从 OpenAlex 和 Crossref 找论文，去重、
筛选，并让 DeepSeek 完成结构化研读、独立证据核验和跨论文综合。用户也可以
上传自己合法取得的 PDF。最终得到可下载的 Markdown 调研报告和完整审计记录。

它不是“让多个机器人自由聊天”，而是一条受程序控制的研究流水线。模型负责
语义判断，Harness 负责顺序、状态、并发、重试、恢复和质量。

## 2. 五分钟使用方法

1. 启动程序。
   - macOS 双击项目里的 `start_mac.command`。
   - Windows 双击 `start_windows.bat`。
   - Docker 用户运行 `docker compose up --build`。
2. 浏览器打开 `http://127.0.0.1:7860`。
3. 填写自己的 DeepSeek API Key。Key 仅放在当前进程内存，不写入数据库。
4. 输入中文研究问题和英文检索词。
5. 选择候选论文数、年份和并发数。
6. 可选上传 PDF；勾选“尝试获取开放获取 PDF 全文”。
7. 点击“开始调研”，复制 `job_id`，点击“查询状态”。
8. 完成后下载报告。用 `run_id` 查看证据级别或恢复中断任务。

建议第一次只选择 3-5 篇，用 `deepseek-v4-flash` 验证流程；确认问题和检索词
合适后再扩大到 20-100 篇。并发建议从 2-4 开始，遇到 API 429 再降低。

## 3. 一篇论文经历什么

```text
OpenAlex/Crossref/上传 PDF
        ↓
DOI 与标准化标题去重
        ↓
Screener：相关性、科研质量、新颖性
        ↓
入选论文尝试取得开放 PDF 全文
        ↓
SQLite 队列 → 多个 Reader Worker
        ↓
Verifier 对照原始文本逐条核验证据
        ↓
代码质量闸门
        ↓
Synthesizer 只综合通过核验的卡片
```

## 4. 为什么有两个数据库文件

- `data/research.db`：产品数据库，保存任务、论文、研究卡、核验结果、失败记录、
  Worker 租约和重试次数。
- `data/research_langgraph_checkpoints.db`：LangGraph 检查点，保存大流程运行到哪个
  节点以及节点状态。

程序在处理论文时突然关闭，重启后 LangGraph 恢复大阶段，SQLite Worker 队列
恢复具体论文。这叫“两层断点恢复”。

## 5. 四个 Agent 的职责

- Screener：决定论文是否与问题相关，不负责写最终结论。
- Reader：把原文变成字段固定的研究卡片，并提供证据。
- Verifier：独立对照原文，检查每条证据是否支持结论。
- Synthesizer：只读取通过核验的研究卡片，形成跨论文结论和产品建议。

Agent 之间不传自由聊天记录，而传 Pydantic 校验的数据对象。字段缺失、引用错位
或全文证据没有页码定位都会被程序拒绝。

## 6. 证据级别怎么理解

- `full_text`：来自用户上传 PDF 或合法开放获取 PDF，提取文本带 `[Page N]` 标记。
- `abstract_only`：只有摘要，可以进入报告，但不计入“全文研读产量”。
- `unavailable`：没有可读摘要或全文，记录失败原因，不进入结论。

报告末尾的“系统执行与证据审计”会列出三种数量、检索来源、质量闸门通过数和
失败数。不要只汇报“找到多少篇”，应汇报“多少候选、多少摘要级、多少全文级、
多少通过核验”。

## 7. Harness 架构

```text
Gradio 网页 / CLI
        ↓
LangGraph（顶层状态图与 checkpoint）
        ↓
自研 HarnessRuntime（逐论文队列、并发池、租约、重试）
        ↓
DeepSeek Agent（语义工作）
        ↓
QualityGate + SQLite + Markdown 报告
```

LangGraph 没有替代所有自研代码。它适合管理“检索→筛选→研读→报告”的大图；
逐篇论文的租约、重试、质量统计和产品数据仍由我们的 Runtime 管理。

## 8. 给别人演示时怎么讲

可以按以下顺序演示：

1. “这是本地网页，数据和任务记录保存在用户电脑，只有模型推理和在线检索走网络。”
2. 输入 GNSS 问题和英文检索词，选择 3 篇，上传一篇 PDF。
3. “OpenAlex、Crossref和用户资料会先去重；上传资料不自动获得质量特权。”
4. 启动任务，展示 `job_id` 和 SQLite 已保存任务。
5. “Reader 与 Verifier 可以并发，但综合报告只能读取通过质量闸门的内容。”
6. 打开任务详情，展示全文、摘要和不可用数量。
7. 下载报告，展示最后的证据审计章节。
8. 解释断点恢复：关闭程序后用 `run_id` 从 checkpoint 继续。

## 9. 部署给其他电脑

### Windows

安装 Python 3.11 或更高版本，解压项目后双击 `start_windows.bat`。首次运行会创建
`.venv` 并安装依赖。Windows 防火墙询问时，只需允许本机网络；程序默认只监听
`127.0.0.1`，局域网其他机器不能直接访问。

### macOS

双击 `start_mac.command`。如果系统阻止首次打开，在终端执行：

```bash
chmod +x start_mac.command
```

### Docker

安装 Docker Desktop 后，在项目目录运行：

```bash
docker compose up --build
```

`./data` 映射到容器内，因此重建容器不会删除任务数据库和报告。

## 10. 已知边界

- 自动全文只使用公开的开放获取 PDF，不绕过登录或付费墙。
- 扫描图片型 PDF 没有文字层时会提示失败；后续可以增加 OCR。
- PDF 内复杂表格、数学公式和图片不能仅靠文本提取完整理解。
- “100篇/天”是容量目标，不是质量保证；实际吞吐取决于全文长度、DeepSeek 限流、
  筛选比例和核验失败率。
- 自动测试不等于真实学术正确性，重要决策仍应由人抽查原文。

## 11. 你应该掌握的三个概念

1. Agent 是专业员工，Harness 是项目经理和制度。
2. LangGraph 管大流程，自研 Runtime 管论文级可靠执行。
3. 找到论文不等于读完论文；摘要级、全文级、核验通过必须分开统计。
